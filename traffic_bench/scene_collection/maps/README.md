# `maps/`

Sign-independent Moscow map pool generated by `collect/`.

The pool is queried by `splits/signs.yaml` and later materialized into `data/scenes/<sign>/`.

> **Generated data:** `raw/`, `nets/`, and `crops/` are gitignored and can be regenerated with `collect`.

## Layout

```
maps/
├── raw/                            # OSM extract
├── nets/                           # SUMO network
├── index/                          # Harvest indexes
├── previews/
│   └── junctions_overview.png      # City overview
├── crops/                          # Cropped scene maps
│   ├── junction/{T,X,O}/
│   ├── dual_path/{T,X}/{slot}/
│   └── segment/<scene_id>/
└── splits/
    ├── signs.yaml
    ├── train_ids.json
    ├── test_ids.json
    └── sign_allocations.json
```


| Path        | Purpose                                         |
| ----------- | ----------------------------------------------- |
| `raw/`      | Source OSM extract *(gitignored)*               |
| `nets/`     | `moscow.net.xml` *(gitignored)*                 |
| `index/`    | Junction, segment, and dual-path JSONL catalogs |
| `crops/`    | Materializable scene maps *(gitignored)*        |
| `splits/`   | Train/test split, sign queries, and allocations |
| `previews/` | City-level visualization                        |


## Crop families


|             |                                 |                                    |
| ----------- | ------------------------------- | ---------------------------------- |
| Family      | Path                            | Used by                            |
| `junction`  | `crops/junction/{T,X,O}/`       | 2.x, 3.2, 4.3                      |
| `dual_path` | `crops/dual_path/{T,X}/{slot}/` | 3.1, 3.18, 4.1, 5.7                |
| `segment`   | `crops/segment/<scene_id>/`     | 3.24, 4.6, 5.21, 5.31, 4.2.x, 5.19 |


Junction and dual-path maps are keyed by SUMO `junction_id`. Segment maps are
keyed by corridor `edge_id` / `scene_id` and split by `osm_way_id`.

### Dual-path crops

A dual-path crop represents an atomic `(baseline_dir, compliant_dir)` pair using:

`l_s`, `l_r`, `r_s`, `r_l`, `s_l`, `s_r`

where `l`, `s`, and `r` denote left, straight, and right.

### Segment crops

Segment crops are mid-corridor windows from the full Moscow net (not junction
approaches). Pipeline: `enumerate` → diversity `select` → `crop`. See
[`../collect/segments/README.md`](../collect/segments/README.md).

Gates (`collect/segments/metrics.py`):

- **length ≥ 150 m** — braking 60→20 km/h plus compliance zone;
- **straight** — chord/arc ≥ 0.99;
- **curved** — 0.97 ≤ chord/arc < 0.99.

Harvest crops **all** qualifying ways (~13k). Diversity
`(straight|curved) × (lanes 1|2|3plus)` is enforced at **assign** time
(even quotas within each sign’s query), not at crop time. Train/test stay
place-disjoint on `osm_way_id`.

Each segment stores in `meta.json` / index:

```
road_id
osm_way_id
length_m
straightness
segment_type
lane_count
lane_bucket
vehicle_lane_indices
pass_right_ok
pass_left_ok
crop_window
```

SUMO lane index `0` is the rightmost lane.

Index files: `segments.jsonl` (all candidates to crop),
`segment_{train,test}_ids.json` (place-disjoint way split).


## Sign queries

Sign-specific sampling is defined in `splits/signs.yaml`:


|                       |                                       |
| --------------------- | ------------------------------------- |
| Sign                  | Query                                 |
| 3.24, 4.6, 5.21, 5.31 | `segment_type: straight`              |
| 4.2.1                 | `lane_count_min: 2` + `pass_right_ok` |
| 4.2.2                 | `lane_count_min: 2` + `pass_left_ok`  |
| 4.2.3                 | `lane_count_min: 2`                   |
| 5.19                  | Any segment → `prepare: crosswalk`    |
| 5.15                  | Not harvested                         |


The 4.2.x signs reuse the same segment crops as the speed-sign scenarios. Obstacle placement is handled during evaluation (`detour_expansion.py`).
